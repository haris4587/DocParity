# Security and trust boundaries

- No contract escrow, asset transfers, private-key collection, server signer or arbitrary command execution.
- Evidence retrieval accepts only HTTPS raw GitHub URLs at full immutable commits within the locked repository. Safe paths reject traversal, query strings, fragments and encoded variants. Response status, byte length and SHA-256 must match before interpretation. The GenVM network layer handles transport and redirects; the contract does not claim a streaming pre-download byte cap. Oversized responses are rejected after retrieval.
- Scope is immutable; evidence can be locked once by the assessment owner. Content-derived IDs include the owner address, preventing another account from squatting that owner's identical scope ID.
- Models treat documents, source, reports and challenges as untrusted data. Their output has strict claim coverage, allowed verdicts, bounded reasons and exact evidence quotations. Every validator independently re-fetches and reviews evidence, checks the leader's quotations and compares verdicts/checks. Format validation alone is insufficient.
- Deterministic checks do not execute code and do not prove behavior from string presence. Missing coverage overrides adverse and positive aggregate conclusions. Transport/integrity/report errors yield INCONCLUSIVE; malformed model output or validator disagreement rejects the transaction rather than storing a fabricated review.
- Hashes prove integrity of the supplied bytes, not the authenticity of test execution, repository ownership, completeness or absence of malicious code. Exact text quotations are grounding checks; they do not guarantee correct reasoning. Prompt injection and correlated model errors remain residual risks.
- Anyone can assess or challenge; evidence submission is owner-only. There is one open challenge at a time and three total review rounds. Permissionless challengers can make a verdict temporarily INCONCLUSIVE and consume review capacity. No time-based settlement, economic anti-spam or assertion of production-grade dispute resistance is provided.
- Frontend renders user-controlled text through escaping. External evidence links are constrained on chain; outbound links use noreferrer. Wallet account/network changes clear the active signer. Writes are never blindly retried after a transaction hash is returned. Receipt finality and successful execution are checked separately.
- Browser wallets retain their keys. Studio built-in accounts remain within Studio; the website prepares call packets rather than impersonating the Studio wallet. Never paste a private key into this dashboard.

Report issues by opening a GitHub issue with a minimal public reproduction; avoid publishing sensitive repository content or credentials. For a suspected exploit, omit exploit-enabling details until maintainers coordinate a fix. This repository has not undergone an independent security audit.
